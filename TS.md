# Техническое задание: AI-ассистент для работы с корпоративной базой данных

---

# 1. Цель продукта

AI-ассистент для работы с корпоративной базой данных, превращающий её в диалоговую систему анализа.

Система позволяет бизнес-пользователям получать ответы на вопросы на естественном языке без знания SQL и без участия разработчика.

---

# 2. Роли пользователей

| Роль | Доступ | Основные задачи |
|------|--------|----------------|
| Менеджер продаж | Только свои данные | Продажи, клиенты, выручка |
| Руководитель отдела | Данные всего отдела | Сравнение сотрудников, KPI |
| Бизнес-аналитик / Администратор | Полный доступ | Глубокий анализ, все таблицы |

---

# 3. Функциональные требования

## 3.1 Интерфейс

- Web-интерфейс в формате чата (аналог ChatGPT / Notion AI);
- пользователь вводит вопрос на естественном языке;
- система показывает сгенерированный SQL до выполнения;
- пользователь подтверждает или отменяет выполнение;
- результат отображается в виде:
  - таблицы;
  - текстового объяснения;
  - графика *(roadmap)*.

---

## 3.2 Генерация и выполнение SQL

Система:

- анализирует схему БД;
- определяет нужные таблицы и поля;
- генерирует SQL-запрос;
- показывает SQL пользователю перед выполнением;
- выполняет только `SELECT`-запросы;
- при необходимости выполняет несколько запросов для одного ответа.

---

## 3.3 Безопасность

Разрешено:
- только `SELECT`.

Запрещено:
- `INSERT`
- `UPDATE`
- `DELETE`
- `DROP`
- `ALTER`
- `TRUNCATE`
- доступ к системным таблицам
- множественные команды в одном запросе.

Настраиваемые ограничения:
- лимит строк результата;
- таймаут выполнения.

Проверка прав:
- доступ проверяется до выполнения SQL;
- пользователь не может увидеть чужие данные;
- при отказе система объясняет причину простым языком.

---

## 3.4 Умная логика

- сравнивает результаты нескольких запросов и формирует единый ответ.

---

## 3.5 Объяснимость результатов

Каждый ответ сопровождается пояснением:

Пример:

> «Учтены только данные за апрель 2026 года.»

---

## 3.6 Обработка ошибок

При любой ошибке система:

- не падает;
- не показывает технические сообщения пользователю;
- объясняет проблему простым языком;
- при возможности исправляет запрос автоматически.

---

## 3.7 Форматы вывода

| Формат | Статус |
|--------|--------|
| Таблица | MVP |
| Текстовое объяснение | MVP |
| График | Roadmap |
| Экспорт Excel / CSV | Roadmap |

---

## 3.8 История и аудит

Сохраняется:

- вопрос пользователя;
- сгенерированный SQL;
- результат;
- время выполнения;
- ошибки;
- действия пользователя.

MVP — сессионно  
Roadmap — долгосрочное хранение.

---

# 4. Данные для работы системы

## 4.1 Источник данных

Система работает с:

- PostgreSQL dump (`.sql`, `.dump`)
- MySQL dump (`.sql`)
- SQLite (`.db`)
- прямым подключением к БД.

---

## 4.2 Описание схемы БД

Необходимо предоставить:

- список таблиц;
- поля и типы данных;
- связи между таблицами;
- PK/FK;
- описание бизнес-смысла таблиц.

Пример:

```text
employees(id, name, department_id, salary)
departments(id, title)
sales(id, employee_id, amount, date)
```

---

## 4.3 Набор бизнес-вопросов

Примеры:

- Какая выручка за апрель 2026?
- Кто лучший менеджер по продажам?
- Сколько новых клиентов за месяц?
- Сравни продажи двух отделов.

Минимум: **30–50 вопросов**.

---

## 4.4 Эталонные ответы

Формат:

**вопрос → SQL → ожидаемый результат**

Пример:

```sql
SELECT SUM(amount)
FROM sales
WHERE date BETWEEN '2026-04-01' AND '2026-04-30';
```

Ожидаемый результат:

`1 245 000`

---

## 4.5 Матрица доступа

| Роль | Доступ |
|------|--------|
| Менеджер | только свои записи |
| Руководитель | данные отдела |
| Администратор | полный доступ |

---

## 4.6 Ограничения выполнения

По умолчанию:

- максимум 1000 строк;
- таймаут 10 секунд;
- ограничение длины SQL;
- обязательное логирование.

---

# 5. Нефункциональные требования

| Параметр | Требование |
|----------|------------|
| Время генерации SQL | ≤ 5 секунд |
| Надёжность | Безопасная обработка ошибок |
| Изоляция доступа | Только разрешённые данные |
| Контроль SQL | Только SELECT |
| Аудит | Полное логирование |

---

# 6. Дополнительные функции

---

## 6.1 Интерактивные дашборды и KPI

Система автоматически формирует кастомные дашборды на основе полученных данных.

Возможности:

- автоматическое построение графиков и диаграмм;
- отображение ключевых KPI в карточках;
- фильтрация по:
  - периоду,
  - отделу,
  - категории;
- обновление данных в реальном времени;
- экспорт в Excel / PDF.

Пример:

После запроса:

> «Покажи динамику продаж за полгода»

пользователь получает:
- таблицу,
- график,
- интерактивный дашборд.

---

## 6.2 Проактивные уведомления (AI Alerts)

Система самостоятельно отслеживает изменения и уведомляет пользователя.

Примеры:

- «Продажи упали на 15% за неделю»;
- «Остатки товара X скоро закончатся»;
- «До выполнения KPI осталось 5%».

---

## 6.3 Выбор AI-модели

Пользователь может выбрать модель ИИ в зависимости от задачи:

### Быстрая модель
Для:
- простых запросов;
- мгновенных ответов.

---

### Продвинутая модель
Для:
- сложной аналитики;
- длинных запросов;
- нескольких связанных таблиц.

---

### Локальная модель
Для компаний с повышенными требованиями безопасности:

- данные не покидают инфраструктуру компании;
- работа в закрытом контуре.

---

# 7. Критерий успеха

Система считается успешной, если:

- стабильно отвечает на 30–50 бизнес-вопросов;
- не выполняет опасные запросы;
- выдаёт понятные объяснения;
- соблюдает ролевую модель доступа;
- корректно обрабатывает ошибки.
