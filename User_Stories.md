# 1.1 Пользовательские сценарии

---

**Сценарий 1: Задать вопрос на естественном языке**
Как бизнес-пользователь, я хочу ввести вопрос текстом и получить ответ из базы данных, чтобы не зависеть от разработчика при получении данных.

Поток:
1. Пользователь открывает веб-интерфейс (чат)
2. Вводит вопрос на естественном языке, например: «Какие товары продавались хуже всего в апреле?»
3. Система анализирует схему базы данных
4. Определяет нужные таблицы и поля
5. Генерирует SQL-запрос
6. Отображает SQL пользователю в отдельном блоке до выполнения
7. Пользователь нажимает «Да» или «Нет»

---

**Сценарий 2: Получить результат и объяснение**
Как бизнес-пользователь, я хочу видеть результат запроса в виде таблицы с текстовым объяснением, чтобы понимать, откуда взялись данные.

Поток:
1. Пользователь подтверждает выполнение SQL
2. Система проверяет права доступа пользователя
3. Выполняет SELECT-запрос
4. Отображает результат в виде таблицы
5. Под таблицей выводится текстовое объяснение:
   - какой период учитывался
   - какие фильтры применялись
   - почему получился такой результат
6. Общий счёт сессии обновляется в логе

---

**Сценарий 3: Получить ответ на сложный многошаговый вопрос**
Как бизнес-пользователь, я хочу задавать вопросы, требующие сравнения нескольких показателей, чтобы получать готовый вывод без самостоятельного анализа.

Поток:
1. Пользователь вводит: «Сколько мне нужно продать, чтобы стать лучшим в отделе?»
2. Система определяет, что вопрос требует нескольких запросов
3. Выполняет запрос для получения данных пользователя
4. Выполняет запрос для получения результата лидера
5. Сравнивает значения и вычисляет разницу
6. Возвращает единый понятный ответ:
   - текущий результат пользователя
   - результат лидера
   - сколько нужно ещё продать

---

**Сценарий 4: Получить понятное сообщение при ошибке**
Как бизнес-пользователь, я хочу видеть понятное сообщение, если система не смогла обработать запрос, чтобы знать, как действовать дальше.

Поток:
1. Пользователь задаёт вопрос
2. Система не может сформировать корректный SQL (несуществующее поле, слишком сложный запрос и т.д.)
3. Если ошибку можно исправить — система корректирует запрос автоматически и уведомляет пользователя
4. Если исправить невозможно — отображается сообщение простым языком без технических деталей
5. Чат остаётся активным, пользователь может задать новый вопрос

---

**Сценарий 5: Работать только со своими данными**  
Как менеджер продаж, я хочу получать данные только по своим клиентам и сделкам, чтобы не видеть информацию других сотрудников.

Поток:
1. Пользователь задаёт вопрос о продажах
2. Система проверяет роль и идентификатор пользователя
3. Автоматически применяет фильтр по принадлежности данных
4. Если вопрос касается чужих данных — запрос не выполняется
5. Пользователь получает объяснение: «У вас нет доступа к этим данным»

---

**Сценарий 6: Блокировка опасных операций**
Как администратор, я хочу, чтобы система блокировала любые операции изменения данных, чтобы база данных была защищена от случайного или намеренного повреждения.

Поток:
1. Пользователь (или AI) формирует запрос, содержащий INSERT / UPDATE / DELETE / DROP / ALTER
2. Система обнаруживает запрещённую операцию до отправки в базу
3. Запрос блокируется
4. Пользователь получает сообщение: «Изменение данных недоступно»
5. Попытка записывается в лог аудита

---

**Сценарий 7: Настройка лимитов запросов** 
Как администратор, я хочу настраивать лимит строк результата и таймаут запроса, чтобы защитить систему от перегрузки.

Поток:
1. Администратор открывает конфигурацию системы
2. Устанавливает максимальное число строк в результате
3. Устанавливает таймаут выполнения запроса
4. При необходимости отключает каждый из параметров независимо
5. При срабатывании лимита или таймаута пользователь получает понятное уведомление

---

**Сценарий 8: Сохранение и просмотр лога действий**
Как администратор, я хочу видеть историю всех запросов пользователей, чтобы контролировать использование системы и разбирать инциденты.

Поток:
1. Пользователь задаёт вопрос и получает ответ
2. Система автоматически сохраняет в лог:
   - вопрос пользователя
   - сгенерированный SQL
   - результат запроса
   - время выполнения
   - ошибки (если были)
3. Администратор открывает раздел аудита
4. Видит полную историю действий по всем пользователям
5. Обычные пользователи к логу доступа не имеют

---

**Сценарий 9: Экспорт результата в файл**
Как бизнес-аналитик, я хочу выгрузить результат запроса в Excel или CSV, чтобы продолжить работу с данными в привычных инструментах.

Поток:
1. Система отображает результат запроса в виде таблицы
2. Пользователь нажимает кнопку «Экспорт»
3. Выбирает формат: .xlsx или .csv
4. Файл скачивается на устройство пользователя
5. Файл содержит те же данные, что отображались в таблице

---

**Сценарий 10: Получить интерактивный дашборд**
Как бизнес-пользователь, я хочу получать результаты анализа в виде интерактивного дашборда, чтобы быстрее анализировать показатели и видеть динамику данных.

Поток:

1. Пользователь задаёт аналитический вопрос:
   «Покажи динамику продаж за последние 6 месяцев»
2. Система анализирует запрос
3. Выполняет необходимые SQL-запросы
4. Формирует:

   * таблицу результатов
   * график динамики
   * KPI-карточки
5. Пользователь может:

   * изменять период
   * фильтровать данные
   * переключать тип визуализации
6. Дашборд обновляется без повторного ввода запроса

---

**Сценарий 11: Получить автоматическое уведомление об изменениях**
Как руководитель отдела, я хочу автоматически получать уведомления о важных изменениях показателей, чтобы быстро реагировать на проблемы.

Поток:

1. Система периодически анализирует данные
2. Обнаруживает отклонение:
   «Продажи упали на 15% за неделю»
3. Формирует AI-уведомление
4. Отправляет уведомление пользователю
5. Пользователь открывает уведомление
6. Система показывает:

   * причину уведомления
   * затронутые показатели
   * сравнительные данные
7. Пользователь может перейти к подробному анализу

---

**Сценарий 12: Настроить AI-уведомления**
Как бизнес-пользователь, я хочу самостоятельно настраивать условия уведомлений, чтобы получать только важную для меня информацию.

Поток:

1. Пользователь открывает раздел AI Alerts
2. Выбирает показатель для отслеживания
3. Устанавливает условие:

   * падение продаж
   * рост расходов
   * снижение KPI
4. Указывает порог срабатывания
5. Сохраняет правило
6. Система начинает автоматический мониторинг
7. При выполнении условия пользователь получает уведомление

---

**Сценарий 13: Выбрать AI-модель для обработки запроса**
Как бизнес-пользователь, я хочу выбирать AI-модель в зависимости от сложности задачи, чтобы получать либо быстрый ответ, либо более глубокий анализ.

Поток:

1. Пользователь открывает настройки запроса
2. Выбирает режим:

   * быстрая модель
   * продвинутая модель
   * локальная модель
3. Система отображает описание выбранного режима
4. Пользователь отправляет запрос
5. Система использует выбранную модель для:

   * генерации SQL
   * анализа данных
   * формирования ответа
6. Пользователь получает результат в соответствии с выбранным режимом

---

**Сценарий 14: Использование локальной AI-модели**
Как администратор компании, я хочу использовать локальную AI-модель, чтобы корпоративные данные не покидали инфраструктуру организации.

Поток:

1. Администратор включает локальную модель в настройках системы
2. Система переключает обработку запросов на локальный AI-сервис
3. Пользователь отправляет запрос
4. Генерация SQL и анализ выполняются внутри инфраструктуры компании
5. Внешние AI-сервисы не получают доступ к данным
6. Система уведомляет пользователя о работе в защищённом режиме

---

**Сценарий 15: Экспорт дашборда и графиков**
Как бизнес-аналитик, я хочу экспортировать дашборд и графики в PDF или Excel, чтобы использовать их в отчётах и презентациях.

Поток:

1. Пользователь открывает сформированный дашборд
2. Нажимает кнопку «Экспорт»
3. Выбирает формат:

   * PDF
   * XLSX
4. Система формирует файл
5. В файл включаются:

   * таблицы
   * графики
   * KPI-карточки
6. Пользователь скачивает готовый файл

---

**Сценарий 16: Работа с обновляемыми KPI**
Как руководитель отдела, я хочу видеть KPI в реальном времени, чтобы быстро оценивать эффективность команды.

Поток:

1. Пользователь открывает аналитический дашборд
2. Система загружает актуальные показатели
3. KPI отображаются в отдельных карточках:

   * продажи
   * выручка
   * выполнение плана
4. Система автоматически обновляет значения
5. При критическом изменении KPI формируется AI-уведомление
6. Пользователь может перейти к детальному анализу показателя
